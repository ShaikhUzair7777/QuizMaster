# QuizMaster

QuizMaster is a Java 25 LTS Maven WAR application using Jakarta Servlets/JSP, Tomcat 10.1, and Supabase Auth/PostgREST. AI-generated quizzes use Gemini from the server; the browser never receives the Gemini or Supabase service-role keys.

## Prerequisites

- JDK 25 LTS
- Maven 3.9+
- Apache Tomcat 10.1
- A Supabase project with the root `database/schema.sql` applied
- A Gemini API key for AI quiz generation

## Configuration

Configure these server-side environment variables (names only):

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `GEMINI_API_KEY`
- `GEMINI_MODEL` (optional; defaults to `gemini-2.5-flash`)

Never place credentials in browser code, a public file, or a commit. The root `.gitignore` excludes `.env` and `.env.*`, while allowing `.env.example`.

The application loads environment variables, JVM properties, or a `.env` in its working/Tomcat configuration directories. After changing settings, restart Tomcat.

Gemini reference: [models](https://ai.google.dev/gemini-api/docs/models), [structured output](https://ai.google.dev/gemini-api/docs/structured-output), and [text generation](https://ai.google.dev/gemini-api/docs/text-generation). Gemini uses an `x-goog-api-key` header; API keys are not query parameters. The default model can be changed with `GEMINI_MODEL` if Google's model availability changes.

## Database setup and migration

In the Supabase SQL Editor, apply the root `database/schema.sql` for a new database, then apply migrations `001_ai_quiz_generation.sql`, `002_learning_topic_catalog.sql`, `003_idempotent_ai_quiz_saves.sql`, and `004_playable_quiz_library.sql` in order. For an existing database, apply the migrations in that order. These migrations do not drop tables or delete existing data.

Migration 001 adds explanations and question-count maintenance, and installs the original private-quiz RPC. Migration 002 adds a separate, service-role-readable `learning_topics` table and repeatably seeds 50 curated topic guides using stable slugs; its upsert does not touch user-created quizzes. These guides contain metadata, not playable questions, and the dashboard labels them accordingly. Migration 003 adds a unique generation-request key and an idempotent transaction RPC so retrying a save cannot create a duplicate private quiz. Migration 004 seeds 15 additional published quizzes with 45 real multiple-choice questions across programming, psychology, AI/data science, computer science/IT, and reasoning. Together with the three original quizzes, that gives the dashboard 18 playable quizzes. The seed uses stable IDs, inserts without overwriting existing rows, and calculates displayed question counts from stored questions. It also adds the `questions.explanation` column if it is missing, so it can recover safely if migration 001 was skipped. It is a curated starter set, separate from private quizzes generated by Gemini.

Migrations are not applied automatically by the application. Apply migration 004 in the Supabase SQL Editor before expecting the additional playable quizzes on a live dashboard; do not paste credentials into the application or migration.

Generated quizzes are saved with `published = false`, and `created_by` is taken from the authenticated server session. Student-facing operations check ownership on the server. The private-quiz RPCs are executable only by the Supabase `service_role`, which must remain server-side.

If **Save & take quiz** reports a database setup error, verify migrations `001_ai_quiz_generation.sql` and `003_idempotent_ai_quiz_saves.sql` were run in the same Supabase project configured for the app. Saving depends on the idempotent RPC added by migration 003.

## Build and deploy

From the project root:

```powershell
mvn test
mvn clean package
```

Deploy `target\quizmaster.war` to an Apache Tomcat 10.1 `webapps` directory. For example:

```powershell
$tomcatHome = "C:\path\to\apache-tomcat-10.1"
Copy-Item .\target\quizmaster.war "$tomcatHome\webapps\quizmaster.war"
& "$tomcatHome\bin\catalina.bat" run
```

The `run` command keeps Tomcat in the foreground; stop it with Ctrl+C. Ensure the server process can read the configured environment variables or a private `.env` file in its working or Tomcat configuration directory. The local app URL is `http://127.0.0.1:8080/quizmaster/`.

### Deploy to Render

The repository includes a Dockerfile, Render Blueprint, and GitHub Actions Maven workflow. The Docker build runs the Java 25 test/package lifecycle, then runs the WAR on Tomcat 10.1.61 as a non-root user. The Tomcat connector is configured from Render's `PORT`; the health check uses `/quizmaster/login`.

1. Push the repository to GitHub and create a new Blueprint instance in Render from `render.yaml` (or create a Docker Web Service for the repository).
2. In Render, set `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, and `GEMINI_API_KEY` as secret environment variables. Never add their values to GitHub or `render.yaml`.
3. Select an instance plan with enough memory for Java/Tomcat, deploy, and confirm the health check passes.
4. Ensure Supabase migrations `001`–`004` are applied to the project configured in Render before testing generated quiz saves and the published quiz catalog.

Render deployment and live Gemini/Supabase integration require the owner's Render/Supabase credentials and must be completed in their dashboards. Automated GitHub Actions builds do not make paid Gemini calls.

## Dashboard learning library

The dashboard reads 50 curated topic guides from `learning_topics`, organized under Programming, Computer Science & IT, AI & Data Science, Psychology, and Other Learning Areas. Search examines topic title, category, and description; category and suggested-level filters operate on those same rows. These records have zero stored questions by design: their action generates a new private quiz. Separately, the Published Assessments section and Exam Catalog are backed by actual `published` quiz records and show database question counts. Once migration 004 is applied, they include 15 new ready-to-play starter quizzes in addition to the original three; only published quizzes with stored questions can be started directly.

## AI quiz workflow

Sign in and open **Generate AI Quiz** or select a topic from the dashboard.

1. **Topic mode:** enter only a topic (for example, “Python functions and recursion”), then generate. No notes or upload are needed. Optional category, Beginner/Intermediate/Advanced level, instructions, question count (1–20), and duration (1–300 minutes) further tailor the quiz. Gemini uses its generated knowledge.
2. **Study-material mode:** paste notes or upload UTF-8 `.txt`, `.md`, `.csv`, or a text-based PDF. The prompt directs Gemini to base questions and answers on supplied content instead of unrelated general knowledge. A focus/topic is optional in this mode.
3. Review the read-only draft preview; it does not accept answers or reveal the answer key. Select **Save & take quiz** to save the quiz privately and open its interactive exam. In the exam, select an answer for each question and submit; the result page shows the score and answer review, and the attempt is recorded in **My History**.

The existing Gemini client, configured model, server-only API key handling, structured response format, bounded retry, and strict output validation are reused. If the configured model returns HTTP 404, the client queries Gemini's model list with the server-held API key and retries only models that advertise `generateContent`, preferring text Flash models. If the key exposes no usable text model, the user is told to enable Gemini API access for its Google project and configure `GEMINI_MODEL` to a listed model. Failed provider requests do not consume the user's generation cooldown or hourly allowance. The current database question model supports four-option multiple choice; True/False and mixed-format generation are not offered. Plain-text files are limited to 100 KB, PDFs to 5 MB, and combined extracted/pasted text to 20,000 characters. Uploads are validated and processed temporarily; uploaded files are not retained. Scanned/image-only PDFs are rejected with an OCR limitation message; OCR is not implemented. Invalid, empty, or unreadable source material fails rather than silently falling back to topic questions.

Drafts remain in the user's server-side session for up to 30 minutes; generation is rate-limited to one request every 20 seconds and five per hour per user per application instance. Saving uses the draft ID as an idempotency key. Generated content can be inaccurate; review it before relying on it.

## Smoke-test checklist

1. Apply migration 004 in Supabase, then sign in and verify that at least 15 playable quizzes appear in Published Assessments and the Exam Catalog with correct question counts.
2. Verify the separate topic-guide library can search and filter its five categories and three suggested levels.
3. Open a topic card and generate a quiz without uploading or pasting anything. Confirm preview question numbers and quiz metadata are populated; the generated draft preview is read-only.
4. Select **Save & take quiz**. Confirm the interactive exam opens; its numbered radio-choice cards are clickable and keyboard accessible. Answer changes are saved atomically, and pending saves complete before submission.
5. Submit and verify the server-computed score appears in the result page and the attempt appears in **My History**.
6. Retry the same save request/draft and verify no second quiz record is created.
7. Verify the exam screen does not contain the answer key or explanations.
8. Select an answer, refresh the exam, and confirm the answer was autosaved. Submit and check the score and explanations on the result page.
9. Sign in as another student and verify the first user's private quiz preview and exam URL are unavailable.
10. Generate from pasted notes and a text-based PDF. Try an image-only scan and confirm it receives the OCR limitation message instead of unrelated questions.

If the dashboard reports that its catalog is unavailable, apply migration 002 and check that the server-side Supabase configuration has table access. If save reports that its RPC is unavailable, confirm migrations 001 and 003 are applied. If Gemini returns quota/permission errors, verify the configured key, model, and project access privately on the server. Scanned PDFs require OCR, and the present multiple-choice schema does not support other question types. Do not include raw credentials or provider response bodies in support logs.
